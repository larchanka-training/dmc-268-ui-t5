# Детальная страница мерж реквеста (MR Detail)

## Когда использовать
- Строится страница одного MR по `:iid`.
- Нужно показать результаты валидации: какой валидатор прошёл/упал/выполняется, список замечаний.
- Нужны результаты пайплайнов (CI) и набор чек-листов для MR.

## Структура страницы
```
src/pages/MrDetailPage.tsx  — страница-контейнер с параметром :iid
src/features/mr-detail/
  ├── MrHeader.tsx          — шапка: титул, ветки, автор, статусы
  ├── ValidationBlock.tsx   — блок результатов валидации / чек-лист
  ├── useMrDetailQuery.ts   — хук получения данных MR
  └── sections/            — дочерние секции (пайплайны, замечания, диффы)
```

## Маршрут и параметры
Маршрут вида `/:iid` (под маршрутом списка) либо `/mr/:iid`. `:iid` получать из `useParams`, передавать в `useMrDetailQuery(iid)`.

```tsx
const { iid } = useParams<{ iid: string }>();
const { data, isLoading, isError } = useMrDetailQuery(iid);
```

## Требования к данным
Подписываться на живой статус валидации:
- Общий статус MR (см. `validation-status`).
- Список валидаторов с индивидуальными статусами (чёкапинг своей структуры, а не «всё в одном поле»).
- Результаты пайплайнов CI, привязанные к SHA.
- Замечания/комментарии проверки с автором и ссылкой на строку.

## Блок валидации (ValidationBlock)
Это ядро страницы. Реализовывать как список проверок, где каждая строка:
- имя валидатора / правило;
- статус через единый компонент `validation-status`;
- время/длительность и ссылка на подробности (лог, детальный отчёт).

Живое обновление: пока хотя бы одна проверка в статусе running/pending — включить **polling** (см. `query-data`), отключить его, когда всё завершено. Не дёргать цикл навсегда.

## Замечания (comments / review findings)
- Группировать по валидатору/сущности.
- Каждое замечание: текст, автор, критичность (Tag), ссылка на файл/строку диффа (deep-link на GitLab).
- Пустое состояние с явным «Замечаний нет» (зелёная индикация).

## Диффы MR
Если показываются изменения — свернуть размер: постраничная подгрузка диффов, не грузить весь MR целиком при первом рендере.

## Чек-лист готовности
- [ ] Параметр `iid` из роута корректно прокинут в хук данных.
- [ ] Блок валидации использует единый компонент статусов (`validation-status`).
- [ ] Polling включён пока идёт `running`/`pending` и отключён после завершения.
- [ ] Обработаны `isLoading` / `isError` (скелетон, «MR не найден / недоступен», ретрай).
- [ ] Замечания снабжены deep-link на файл/строку.
